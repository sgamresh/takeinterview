# India QA Role Research

Research observed: 2026-10-21  
Market: India  
Scope: software QA and test engineering roles

## Method

Reviewed public job-board search pages and representative listings on Naukri and Indeed. Search results are dynamic and can contain duplicates, staffing-agency reposts, stale postings, or inaccurate skill tags. The catalog therefore favors recurring competencies across different employers and treats tools as examples, not universal requirements. Role inclusion is based on distinct assessment needs, not job-board result counts. Posting titles and experience ranges are indicative rather than formal level definitions.

## Market Signals

- Manual QA/Test Analyst postings use varied titles, including Manual Tester, Test Engineer, QA Engineer, and Quality Engineer. Recurring work includes understanding requirements, designing and executing functional/regression tests, reporting defects, and collaborating in Agile teams. API and SQL knowledge appear in some supposedly manual roles, but should not be assumed mandatory for every manual QA position.
- QA Automation/SDET listings frequently combine programming, framework design and maintenance, browser automation, API testing, CI execution, data validation, and debugging. Selenium remains present alongside Playwright and other frameworks; tool choice varies by employer and product.
- QA Lead/Test Lead postings combine test strategy and planning, test coverage and execution oversight, automation direction, defect and risk management, quality reporting, team guidance, and stakeholder communication. Technical depth varies with domain and team structure.
- API QA roles have a distinct focus on HTTP/REST or service contracts, payload and status validation, negative/error scenarios, API automation, and data or integration checks. Postman, REST Assured, and Swagger/OpenAPI appear as examples; the competency is broader than one tool.
- Mobile QA roles are distinct in their platform/device coverage: Android and iOS behavior, compatibility, lifecycle and connectivity scenarios, plus manual or automated mobile flows. Appium appears in automation listings; some mobile roles emphasize manual device testing.
- Performance testing appears as a distinct hiring track. Common themes include workload and load-profile design, test scripting, measurements, bottleneck analysis, system/APM diagnostics, and communicating results. JMeter, LoadRunner, NeoLoad, and monitoring tools vary across employers.

## Catalog Mapping

The catalogs separate role competencies from product/tool choices. Existing role, module, and SDET template IDs were retained where possible for saved drafts and re-evaluations. New roles are included for API, mobile, and performance testing because the reviewed listings show distinct assessment needs. The generic rating scale remains unchanged; these module descriptions identify topic areas, not anchored 1-5 behavioral criteria.

Template weights sum to 100 and every module listed for a role has a positive weight because the current UI requires a rating for every rendered module. The templates are starting points and should be adjusted to the employer's product domain and job description.

## Technical References

These references validate competency boundaries and terminology. They are not evidence of hiring demand:

- [ISTQB Certified Tester Foundation Level v4.0](https://www.istqb.org/certifications/certified-tester-foundation-level): testing fundamentals, test design, test planning, risk, monitoring, defect management, and automation tradeoffs.
- [Selenium documentation](https://www.selenium.dev/documentation/) and [Playwright introduction](https://playwright.dev/docs/intro): browser automation frameworks and test execution contexts.
- [Appium documentation](https://appium.io/docs/en/latest/): UI automation across mobile and other app platforms.
- [Apache JMeter User's Manual](https://jmeter.apache.org/usermanual/index.html): test-plan construction, load execution, analysis, and reporting.

## Maintenance

Refresh this review periodically. Prefer postings from the last 6-12 months, diversify employers and sources, note the observation date, and avoid treating search-result counts or one-off tool mentions as universal requirements.
